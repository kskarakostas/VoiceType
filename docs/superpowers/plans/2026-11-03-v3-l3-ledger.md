## Step A: sender.tab.url in frames

Probe, Chromium 153.0.8010.12 headless through Playwright, built extension, a second `runtime.onMessage` listener in the service worker recording every sender, on `http://localhost:8765/fields.html`:

| Frame | `sender.url` | `sender.origin` | `sender.tab.url` |
|---|---|---|---|
| top | `http://localhost:8765/fields.html` | `http://localhost:8765` | `http://localhost:8765/fields.html` |
| same-origin iframe | `http://localhost:8765/frame.html` | `http://localhost:8765` | same top URL |
| cross-origin iframe | `http://127.0.0.1:8765/frame.html` | `http://127.0.0.1:8765` | same top URL |
| `about:blank` iframe | `about:blank` | `http://localhost:8765` | same top URL |
| `srcdoc` iframe | `about:srcdoc` | `http://localhost:8765` | same top URL |
| sandboxed iframe | `http://127.0.0.1:8765/frame.html?sandboxed` | `null` | same top URL |

After `history.pushState`, a frame's next message reports the pushed URL in `sender.tab.url`.

Result: the spec's V7 resolution holds. VERIFIED (probe output above). A prerendered document is the exception: its message carries the previous page's URL (found by the final review, see Rulings). Not probed: fenced frames, a frame message sent during a top-level navigation.

Also seen, and used by the plan:
- `tabs.query({})` from the service worker: `url` present on the http tab, absent on `chrome://version`, on `about:blank` and on the extension's own options tab. So a tab with no `url` means no rule, and `about:blank` and extension tabs fall under "Not available on this page".
- `chrome.action.openPopup()` works headless and opens a real `POPUP` context, but Playwright gets no page for it. Its target is visible only through CDP.

## Rulings during execution (controller)

- Task 1: the plan stripped the trailing dot before `www`, so `www.` gave `www` against its own table and today's null. `www` goes first. Cost if wrong: none.
- Task 2: `SAVE_SETTINGS` keeps `current.siteRules`, so a stale page can never write rules; a payload field is dropped with `{ success: true }`. Deleting a custom mode still repairs rules. Cost if wrong: a later page writing rules through `commit` silently stores nothing.
- Task 3: the boot gate also covers `focusOut` and window blur; a blur during the wait would otherwise show a pill 200 ms later on a hidden site. `.finally` replaces the plan's `.then`, `focusOut` follows the first `focusIn`, and `start()` records `lastField`, since all three restore 2.2 behaviour the gate narrowed. Cost if wrong: small edits.
- Task 4: a failed popup save writes the focused control (`paint(true)`), since a plain render skips it and leaves the refused value showing. With settings unloaded on a usable page both the line and the controls stay hidden. Hide pill is a checkbox where spec 6.1 says switch; the design has no switch control. Cost if wrong: a restyle.
- Task 5: rows read the stored key, not `ruleFor`, which re-normalizes. The table stacks through a container query, since a window query cannot see the sidebar. Cost if wrong: a restyle.
- Task 6: the e2e implementer fixed a bug from 5502e17 (2026-09-27), in its own commit: the zero-width dot's overflow took clicks on the left of the mode button (offsets -12, -6 and 0 px did nothing). Corrected in the final wave to `.dot::before, .dot::after`, so the idle hover box stays whole. Worth a CHANGELOG line in L6.
- Final review: a recording with its field scrolled out showed no indicator on any site, pre-existing since 2.x. Fixed here, not moved to L5: it is a spec anti-goal and an L3 acceptance line, and Minimal would cover hidden sites only. `Pill` falls back to the corner while it has a state or a status to show; `position.js` is untouched. Cost if wrong: L5 reworks a few lines.
- Final review: a prerendered page's message carries the previous page's URL, so it took the wrong site rule, and a page from bfcache kept a stale one. One boot path now reads settings when the document becomes current. Cost if wrong: one extra `GET_SETTINGS` per restore.
- Final review: `siteKey` strips repeated leading `www.` and repeated trailing dots, so it is idempotent. This widens V8's "a leading `www.`" for hosts that barely exist. PROPOSED, for K. S. Karakostas's approval. Cost if wrong: `www.www.a.com` shares a rule with `a.com`.
- Parked: `siteKey` stays non-idempotent for a numeric tail with two or more trailing dots (`1..`). Such hosts do not resolve, and this subtopic produced findings four rounds running, so it stops here. Cost if wrong: one useless rule.
- Smoke: Chromium percent-encodes a space in a host where Node's parser throws, so `not a host` stored the rule `not%20a%20host`, invisible to unit tests. `siteKey` now refuses anything but letters, digits, `_`, `-`, `.` or a bracketed IPv6 literal, and an e2e runs the key table in Chromium. Cost if wrong: a tab on a hand-made hostname holding `$` or quotes gets no rule.
