# VoiceType 3.0 master plan

Prepared 2026-11-03 for K. S. Karakostas. Design: `docs/superpowers/specs/2026-11-03-v3-design.md` (cited below as "spec"). Structure follows `docs/superpowers/plans/2026-09-27-phase-1-kickoff-prompt.md`, split into one kickoff per lane.

## How to run it

1. Run the lanes in order, one fresh Claude Code session per lane, opened in this repository. Paste that lane's kickoff block.
2. All lanes commit to one branch, `v3`, created off `main` by L0. Lanes do not run in parallel: L1 to L5 all edit the settings page.
3. Each lane ends with: `npm test`, `npm run test:e2e`, `npm run build` green; its ledger `docs/superpowers/plans/2026-11-03-v3-<lane>-ledger.md`; a browser smoke checklist for you. Run that checklist before starting the next lane, and put the result in the next kickoff's SMOKE line.
4. Only L6 bumps the version and writes `CHANGELOG.md` (the manifest test requires the top heading to equal the manifest version).
5. Git integration stays with you: L6 hands you the merge, tag and push commands (push only through `github-kska`).

## Rules for every lane

Unchanged from 2.x: plain JavaScript with JSDoc; esbuild and Vitest; `minimum_chrome_version` 140; no new permissions; keys never reach content scripts or pages, and the offscreen document never reads, stores or handles one; user data set with `textContent` only; no em or en dashes anywhere; commits carry only the change description, no AI attribution trailers; all subagents on Opus, implementers and reviewers (spec V22; this overrides the global Sonnet default for this project); address me as Kostas, in files K. S. Karakostas.

Per lane:
- Before planning, read the spec sections listed, the previous lane's ledger, and the project memory. Verify against current Chrome docs any platform behaviour the lane relies on that the spec does not mark VERIFIED.
- Ask every open design question in one `AskUserQuestion` (at most 4 questions, enumerated options, one recommended). A change to a PROPOSED spec decision needs my approval and goes into the ledger.
- `superpowers:writing-plans` writes `docs/superpowers/plans/2026-11-03-v3-<lane>.md` with a Review Focus section and full TDD steps. Then `superpowers:subagent-driven-development` executes it.
- Do not touch files another lane owns unless the plan says why; anything found and not fixed goes into the ledger as `deferred`. Shared files (`src/shared/messages.js`, the settings page shell) are edited append-only by later lanes.
- Settings migration belongs to L0 alone: later lanes never change `SETTINGS_VERSION` or the migration routing.
