# VoiceType 3.0 L0 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settings schema v3 with migration from v1 and v2, a full settings page in a tab holding every 2.2 setting, and a slim quick-panel popup, on branch `v3`.

**Architecture:** Pure shared modules (`src/shared/dictionary.js`, `src/shared/sites.js`) feed the v3 validation in `src/shared/defaults.js`. Both extension pages talk to the service worker through one client (`src/ui/settings-client.js`) that sends only changed top-level fields and re-reads on `chrome.storage.onChanged`. The settings page (`src/options/`) is a hash-routed shell whose sections are ported from today's popup with their tests; the popup becomes a quick panel that opens settings routes per V6.

**Tech Stack:** Chrome MV3 (minimum Chrome 140), plain JavaScript with JSDoc, esbuild, Vitest with jsdom, Playwright 1.63 with bundled Chromium.

**Spec:** `docs/superpowers/specs/2026-11-03-v3-design.md` (sections 1 to 4, 6.1, 7; decisions V6, V18, V20, V21). Master plan: `docs/superpowers/plans/2026-11-03-v3-master.md` (L0 row). Step A evidence and the three rulings by K. S. Karakostas: `docs/superpowers/plans/2026-11-03-v3-l0-ledger.md`.

**Author:** K. S. Karakostas. Prepared 2026-11-03.

## Global Constraints

- `minimum_chrome_version` stays `"140"`; permissions stay exactly `storage`, `scripting`, `offscreen`; host permissions stay `["<all_urls>"]`. `options_ui` is a manifest key, not a permission.
- Zero runtime dependencies; devDependencies unchanged.
- Keys never reach content scripts or web pages: `toPublicSettings` excludes `keys`, `siteRules` and `dictionary`.
- User data is set with `textContent` only; no `innerHTML`, no inline handlers, no emoji in HTML files.
- No em or en dashes anywhere (code, comments, copy, docs). In files the author is K. S. Karakostas.
- No version bump and no `CHANGELOG.md` heading in this lane. `SETTINGS_VERSION` and the migration routing are L0's alone.
- Both pages follow `prefers-color-scheme`, keep visible focus rings (`:focus-visible` outline `2px solid var(--focus)`) and keyboard order; text tokens meet 4.5:1; no font size under 12 px.
- Commit messages carry the change description only: no trailers, no AI attribution.
- Every task ends with `npm test` green (report `N/N`) and `npm run build` clean. Task 7 also runs `npm run test:e2e`.
- Test runner: `npx vitest run <path>` for one file.

## Review Focus

1. A settings tab open for hours, then the popup (or another tab) changes the active mode, then the user edits a recording limit in the old tab. Expected: the save carries `minRecordingTime` only; the newer `activeMode` survives. Pinned in Task 5 (`sections-core.test.js`, "a save after an external change sends only the edited field").
2. An external settings change lands while the user types in a text field with its debounce pending. Expected: the field keeps the typed text and caret, and the pending save still sends the typed value. Pinned in Task 5 ("an external change never overwrites the field being typed in").
3. A save fails after an external re-read changed other fields. Expected: only the failed patch's fields roll back; the externally changed field keeps its new value. Pinned in Task 5 ("a failed save rolls back only its own fields").
4. A v2 store with keys, custom modes and messy keywords (duplicates in different case, blanks, more than 100). Expected: keys and modes identical after migration; `dictionary.any` holds the first 100 unique trimmed terms; `keywords` gone. Pinned in Task 2 ("v2 with keys, modes and keywords keeps them all").
5. A settings URL with a malformed or unknown hash (`#`, `#settings/`, `#settings/provider/x`, `#nope`, `#%E0`). Expected: Home renders, nothing throws, a bare `#settings` opens Provider. Pinned in Task 4 (`routes.test.js`, "unknown and malformed hashes resolve to home").

- Produces (`src/options/options.js`):
  - `initOptions({ chrome, document, window }): Promise<{ readonly settings: Settings, readonly loaded: boolean, readonly route: string }>`.
  - Section registration used by Tasks 5 and 6: `/** @typedef {{ render(): void, typingSaves?: TypingSave[] }} Section */` and a `PageContext` object built once and handed to each section factory:
    ```js
    /** @typedef {{
     *   document: Document, window: Window, chrome: typeof chrome, mac: boolean,
     *   $: (id: string) => HTMLElement,
     *   settings: () => Settings, loaded: () => boolean,
     *   commit: (mutate: (draft: Settings) => void, successText?: string) => Promise<boolean>,
     *   send: (message: object) => Promise<any|null>,
     *   toast: (text: string, tone?: 'info'|'success'|'error') => void,
     *   typingSave: (save: () => unknown) => TypingSave,
     *   setTimer: (fn: () => void, ms: number) => number, clearTimer: (id: number) => void,
     * }} PageContext
     * @typedef {{ readonly pending: boolean, schedule(): void, cancel(): void, flush(): unknown }} TypingSave
     */
    ```
    `typingSave` is today's helper (`src/popup/popup.js:115-139`) with `TYPING_SAVE_MS = 400`. `SECTIONS` in `options.js` is a list of factories `(ctx: PageContext) => Section`; Task 4 ships it empty and Tasks 5 and 6 append to it.
  - `commit(mutate, successText)`: clone `settings`, apply `mutate` to the clone, `patch = changedFields(settings, clone)`; an empty patch resolves `true` with no message sent; otherwise set `settings = clone`, render, and `client.save(patch)` (not sent, error toast `Settings are not loaded. Nothing was saved.` and rollback when not loaded). On failure restore only the patched fields from the pre-commit snapshot (for `keys` only the patched providers), render, toast the reply's error or `Could not save settings.`, resolve `false`.
  - External change: `client.onExternalChange` triggers a re-read (`client.load()`, then `settings = fresh` and render) unless a save is in flight, in which case one re-read runs when the last in-flight save settles. Render never writes a focused field (the existing rule).
  - Closing: `pagehide`, and `visibilitychange` to `hidden`, flush every section's `typingSaves`. No `beforeunload`, no Esc handler.
  - Load failure: banner text `Could not load settings. Reload this page.`, saving disabled.
