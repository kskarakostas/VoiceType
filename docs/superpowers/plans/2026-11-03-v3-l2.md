# VoiceType 3.0 L2 Dictionary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the L0 vocabulary field with a Dictionary page grouped by language, with CSV import and export.

**Architecture:** Pure term rules go in `src/shared/dictionary.js`, next to the helpers settings validation and the pipeline already use. A new pure module `src/options/dictionary-csv.js` holds the RFC 4180 parser, the export and the all-or-nothing import. `src/options/sections/dictionary.js` renders one card per group from `ctx.settings()`, keeps cards alive across renders so a field being typed in is never touched, and saves through `ctx.commit` as the other sections do. Nothing outside the settings page changes: the pipeline already sends `flattenDictionary(settings.dictionary)`.

**Tech Stack:** Chrome MV3 (minimum Chrome 140), plain JavaScript with JSDoc, esbuild, Vitest with jsdom, Playwright with bundled Chromium.

## Decisions this plan applies

K. S. Karakostas, 2026-11-03 (AskUserQuestion):
- A CSV import is all or nothing: the first bad line is reported with its number and nothing is imported.
- A term typed but not confirmed is added when the field loses focus, the tab is hidden, or the page closes; Enter and commas work as the spec says. Refused text stays in the field.
- A first line of exactly `language;term` switches that file to `;` as its separator (Excel in a Greek locale). Export stays comma.

PROPOSED (controller, within spec 6.3):
- Import format: a first record of `language,term` means two columns; any other file is one column. A headerless two-column file is refused with a message naming the header, so a term list containing commas is never misread as language codes. Trailing empty columns (Excel pads them) are ignored. Language codes are trimmed and compared lowercase.
- The `all languages` card always shows, even when `any` is not stored. Its Remove group button shows only when it has terms. Removing a group's last chip keeps the card empty; only Remove group deletes a language card.
- An import refuses a file containing U+FFFD or NUL (a non-UTF-8 file decoded by `Blob.text()`) and a file over 1,000,000 bytes.
- The over-64 check applies to terms the import would add. A term already in the dictionary is skipped first, so a long term stored by 2.2, which had no length rule, round-trips without an error.
- A line break inside a quoted term becomes a space; providers would turn it into one anyway.
- No formula escaping on export (a leading `'` would break the round trip the spec requires; the file holds the user's own terms, and an imported hostile file would be just as dangerous opened directly).
- `parseKeywords` and `formatKeywords` go, since this lane removes their only caller.

## Review Focus

### Task 2: CSV module

**Files:**
- Create: `src/options/dictionary-csv.js`
- Test: `test/unit/options/dictionary-csv.test.js`

**Interfaces:**
- Consumes: from `src/shared/dictionary.js`: `orderedGroupKeys`, `isDictionaryGroup`, `countTerms`, `flattenDictionary`, `isTermTooLong`, `MAX_TERM_LENGTH`, `MAX_KEYWORDS`.
- Produces (`src/options/dictionary-csv.js`, no chrome and no DOM):
  - `MAX_IMPORT_BYTES = 1_000_000`
  - `serializeDictionary(dictionary): string`: U+FEFF, `language,term\r\n`, then `<group>,<term>\r\n` per term in display order. A field containing `,`, `;`, `"`, CR or LF is quoted, inner quotes doubled. Empty groups give no rows.
  - `parseCsv(text: string, delimiter?: string): { ok: true, records: Array<{ line: number, fields: string[] }> } | { ok: false, line: number, reason: string }`: strips a leading U+FEFF; CRLF, LF and lone CR end a record; `line` is the 1-based line a record starts on, counting line breaks inside quotes; records with only blank fields are dropped. Quotes open a quoted field only at its start; elsewhere a quote is a literal character. `""` inside quotes is one quote. Text after a closing quote fails with reason `text follows a closing quote`; end of input inside quotes fails at the record's line with reason `a quote is never closed`.
  - `importDictionaryCsv(text: string, dictionary): { ok: true, dictionary, added: number, skipped: number } | { ok: false, message: string }`: never mutates `dictionary`; returns the same reference when `added === 0`.

Import rules, in order:
1. Text containing U+FFFD or U+0000: `This file is not UTF-8. Save it as CSV UTF-8 and try again. Nothing was imported.`
2. Separator `;` when the first non-blank line, trimmed, matches `/^language;term;*$/i`; else `,`.
3. `parseCsv`; a failure gives `Line N: <reason>. Nothing was imported.`
4. The first record, trimmed, lowercased, trailing empties dropped, equal to `['language','term']` means two columns and is skipped; otherwise one column.
5. Two columns: a non-blank field past the second gives `Line N has more than two columns. Quote terms that contain commas. Nothing was imported.` The code is `fields[0].trim().toLowerCase()`; not `isDictionaryGroup` gives `Line N: unknown language "<code, first 32 characters>". Nothing was imported.` This check runs even when the term is blank.
6. One column: a non-blank field past the first gives `Line N has more than one column. Add a language,term header or quote terms that contain commas. Nothing was imported.` The group is `any`.
7. A term has runs of CR and LF replaced by one space, then is trimmed; empty terms are dropped.
8. No rows left: `{ ok: false, message: 'No terms in that file.' }`.
9. For each row in file order: a term already stored or earlier in the file (case-insensitive) counts as skipped; else over 64 code points gives `Line N: the term is over 64 characters. Nothing was imported.`; else it is added to its group, after the group's stored terms.
10. `countTerms(dictionary) + added > MAX_KEYWORDS` gives `This import would go over the 100 term limit by <over>. Nothing was imported.`

Rendering rules:
- Cards are keyed by group and kept across renders, and an existing card is never moved, so typed text and focus survive. Groups shown: `any` always, then `orderedGroupKeys`. A new card goes in before the next existing one. A card whose group is gone is removed.
- A card rebuilds its chips only when its term list differs from the last one it drew. If a chip button had focus and its term is still there after the rebuild, focus returns to it.
- Remove group shows on a language card always, and on `any` only when it has terms.
- The language select is rebuilt from the languages not present, unless it has focus.

Behaviour:
- Enter on an add field, or its `blur`, runs one add with `addTerms`. The field is set to the refused terms joined with `, ` before `ctx.commit` runs, so a blur right after Enter finds nothing new. When `commit` resolves false and the field is still empty, the text is put back. Enter calls `preventDefault`.
- A refusal shows in the card's message, from the first refused term: `Already in <groupLabel>`, `Terms can have at most 64 characters`, or `The dictionary is full (100 terms)`, with `data-tone="error"`. An add with no refusal clears the message. Empty text does nothing and leaves the message alone.
- A chip button commits `removeTerm`, then moves focus to the next chip's button in that card, or the previous one, or the card's input.
- Remove group commits `setGroupTerms(d, group, [])` and moves focus to the `any` input.
- Add language commits the group with `[]`, then focuses the new card's input.
