# VoiceType 3.0 L4 Sound and clipboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional sounds for start, stop, done and error, and an option to also copy every result to the clipboard, plus the fix for a clipboard write that stalls behind a page prompt.

**Architecture:** The service worker decides everything: the recorder fixes `sounds` and `alwaysCopy` at start, sends `OFFSCREEN_CUE` fire and forget, and awaits `OFFSCREEN_COPY` for at most 1 s before `DICTATION_RESULT`. The offscreen document only plays synthesized cues and copies through a `copy` listener; `clipboardWrite` makes that copy legal with no user gesture. The controller shows " Not copied." when the copy failed. `copyText` gets a time limit so a pending `writeText` never holds a transcript.

**Tech Stack:** Chrome MV3 (minimum Chrome 140), plain JavaScript with JSDoc, esbuild, Vitest with jsdom, Playwright with bundled Chromium.

**Spec:** `docs/superpowers/specs/2026-11-03-v3-design.md` (sections 2 V11 to V13, 3, 5, 6.5, 8). Master plan: `docs/superpowers/plans/2026-11-03-v3-master.md` (L4 row). Spike evidence and decisions: `docs/superpowers/plans/2026-11-03-v3-l4-ledger.md`.

**Author:** K. S. Karakostas. Prepared 2026-11-04.

## Decisions this plan applies

K. S. Karakostas, 2026-11-04 (AskUserQuestion):
- `clipboardWrite` is added; the offscreen document copies.
- `copyText` gets a time limit, on `v3` only.
- "No speech detected." plays the error cue.

PROPOSED (controller, within the spec):
- The start cue plays once the capture is live, not before: spike (c) shows no leak, and the cue then truly means the microphone is on. V13's fallback (cue, wait, capture) is not needed.
- The stop cue plays in `onDone`, when the audio is complete and the microphone released, so it can never reach the recording. It plays only when processing starts: "Too short, ignored" gets no cue.
- `sounds` and `alwaysCopy` are read once, at start, with the rest of the session's settings. A change during a recording applies to the next one.
- A new `AudioContext` per cue, closed after it: an open context holds an audio stream open between dictations.
- The copy uses a `copy` listener, no textarea and no selection, so success is known (`execCommand` returned `true` and wrote nothing in spike (b)) and the text stays exact.
- `denied` plays the error cue (the recording failed; an OS block is no refusal by the page). `noKey` plays none (a configuration refusal; the status says what to do).
- A failure with no readable settings plays no cue: `sounds` is unknown, and off must stay silent.
- A warning result (mode failed, raw text inserted) is a success: done cue.
- " Not copied." is also appended to a warning status on an inserted result. Other outcomes copy through `copyText` and speak for themselves.
- A failure seen only by the content script (no reply, the processing watchdog, a failed insert) plays no cue: the worker alone plays them, and a dead worker cannot.
- `COPY_TIMEOUT_MS` and `WRITE_LIMIT_MS` are both 1000.
- There is no sound preview on the page (not in the spec).

1. The page closes or navigates while the microphone is opening. Expected: no error cue, no reply noise. Pinned in Task 2 (rows 7 and 13).
