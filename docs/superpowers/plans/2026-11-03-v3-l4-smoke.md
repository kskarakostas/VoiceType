# VoiceType 3.0 lane L4 smoke checklist (for K. S. Karakostas)

Branch `v3`, still version 2.2.0 (only L6 bumps the version). Checks the L4 deliverables: the four cues, always-copy, the time limit on a clipboard write, the Sound and clipboard page and the `clipboardWrite` permission. Needs Chrome 140 or newer, a working OpenAI key and a working Gemini key (section 9 uses both; every other section needs one), speakers and a real microphone. Note each item as pass, fail (with the exact on-screen text) or n/a, and put the result in the L5 kickoff's SMOKE line.

Items marked (manual) need a person with real speakers, a real microphone or both: the automated runs mute audio, so `test/e2e/sound-clipboard.spec.js` proves that each cue is asked for, never that it is heard.

Build first, then click the reload icon on the VoiceType card in chrome://extensions:

```bash
npm test
npm run build
npm run test:e2e
```

Reload any open page you test on after reloading the extension.

## 1. The page and its defaults
- Open Settings, Sound and clipboard: Play sounds and Always copy the result are both off, each with its hint.
- With both off, dictate into a field after copying something else: the text lands, and pasting gives what you copied before. No sound plays (manual).
- Tick both, reload the page: both stay ticked. Keyboard only: Tab reaches both, Space toggles, the focus ring shows.
- Shrink the window to phone width, light and dark: no sideways scroll.
- Settings, Usage and data, Reset to defaults: both go back to off.

## 2. Each cue once on success (manual)
- Play sounds on, dictate on a normal site: one rising tone when the pill shows recording, one falling tone when you stop, one bright rising tone when the text is ready. Three tones, none twice.
- Same with the hotkey, tap to start and tap to stop.
- Same with hold to talk: hold the hotkey, speak, release.
- Same with silence auto-stop on (Settings, Recording): the falling tone plays at the auto-stop, then the done tone.
- A mode that fails and inserts the raw text with a warning: the done tone, not the error tone. Note n/a if you cannot provoke one.
- Change Play sounds during a recording: this recording keeps the old value, the next one uses the new one.
- Each tone ends cleanly, with no click or cut at the end. By ear, or with `parec` as in spike (a) of the L4 ledger (the automated smoke found a cut tail here; fixed in 1cfe8b5).
- The first cue after Chrome has been idle for a few minutes still plays, and the dictation is not delayed.

## 3. Silence where silence is due (manual)
- Sounds on, stop within the minimum recording time (default 1 s): the status reads "Too short, ignored". The start tone plays, then nothing: no stop tone, no error tone.
- Sounds on, double tap the hotkey while the microphone opens: the status reads "Too short, ignored". The start tone at most, no error tone.
- Sounds on, record 3 s of silence: the start and stop tones, then the low falling error tone with "No speech detected."
- Sounds on, remove the key, press REC: "Add an API key in VoiceType settings." and no tone. Put the key back.
- Sounds on, record in one tab, press REC in another: "VoiceType is busy in another tab. Try again in a moment." and no new tone.
- Sounds off, trigger any of the above: no tone at all.

## 4. Cancel while starting (manual)
- Sounds on, press REC and close the tab at once: no tone. Chrome's microphone indicator is gone. A start tone means the capture won the race and the close came too late: repeat, and note n/a if you never beat it.
- Dictate in another tab straight after: it starts normally, with no busy status.
- Sounds on, press REC, wait for the start tone, navigate the tab away while recording: the start tone, then nothing.

## 5. Always copy
For each field, turn Always copy on, copy something else first, dictate, then paste into a scratch field. The status reads `Done` and the cost with nothing after it, unless the item says otherwise.
- A textarea on a normal site: the field has the text, the paste gives the same text.
- A contenteditable (a rich editor, or `#ce` on the fixture page): same.
- A cross-origin iframe: run `node test/fixtures/serve.mjs`, open `http://localhost:8765/fields.html`, dictate into the cross-origin frame: same.
- Google Docs: the status reads "Copied to clipboard. The field could not be edited." and the paste gives the text.
- A mode that returns several lines, spoken in Greek: the paste matches the field exactly, line breaks and accents included.
- Close the tab while the result is processing: the paste still gives the text.
- A long hold. Textarea, hold the hotkey for over 5 s, speak, release: the text lands, the status has no "Not copied", and the paste gives the text.
- Long after the last user action, which is the case `clipboardWrite` exists for. Textarea, silence auto-stop on (Settings, Recording): press the hotkey once, speak for over 5 s, stop talking and let the auto-stop end it, with no key or mouse in between: same result.

## 6. The clipboard-only path with no page prompt
- Google Docs, Always copy off, silence auto-stop on (Settings, Recording). Press the hotkey once, speak for over 5 s, stop talking and let the auto-stop end it, with no key or mouse in between: "Copied to clipboard. The field could not be edited." and the text pastes. Chrome shows no prompt with "wants to See text and images copied to the clipboard".
- Same with Always copy on.

## 7. A slow provider with focus moved
- Record a clip long enough that the result comes over 5 s after your click on the other field: that click is itself a user action, so the wait counts from it (use a long take; if your provider answers faster, note n/a). Stop, click another field of the page, then leave the keyboard and mouse alone.
- When the result comes: "The field lost focus. Text copied to clipboard.", the text pastes, neither field was typed into, and no page prompt shows. On 2.2.0 this stalled behind the prompt with no status (L4 ledger, the defect after spike (c)).
- A write that stays pending (open item from Task 3). Copy the build, drop the permission and load the copy instead:

```bash
cp -r dist /tmp/voicetype-no-clipboard-write
sed -i 's/, "clipboardWrite"//' /tmp/voicetype-no-clipboard-write/manifest.json
```

  The copy has its own extension id, so add a key and allow the microphone first. Repeat the slow clip with focus moved, the result again over 5 s after the click: the page prompt may show, and "Could not insert. Click here to copy the text." appears about 1 s after the result, without an answer to the prompt. Click it: the text copies. Dismiss the prompt, remove the copy and load `dist` again.

## 8. The permission
- chrome://extensions, VoiceType, Details: the permissions list reads "Modify data you copy and paste." (the warning Chrome's permission list documents for `clipboardWrite`, quoted in the L4 ledger).
- The upgrade prompt: an update that adds this permission should ask before it re-enables the extension. An unpacked reload may not show that. TO CONFIRM (K. S. Karakostas): if it does not, note n/a here and check it at L6 with a packed or Web Store build going from 2.2.0 to `v3`.

## 9. Speakers and a real microphone (manual)
Spike (c) tested a digital loop only, so a room is still unverified.
- Speakers on, no headphones, at your usual volume, Play sounds on. Press REC, say nothing, stop after 3 s: "No speech detected." A transcript with text in it means the start tone reached the recording: note the exact text.
- Same, speaking one sentence right after the start tone: the transcript has only that sentence, and its first words are not cut.
- Run both on OpenAI, then both on Gemini.

Also check: a Bluetooth headset (the output can switch profile when the microphone opens, so the start tone may be late or lost), the tones at low system volume, and another tab playing audio during a dictation (the tones stay audible).
