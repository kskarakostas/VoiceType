# VoiceType 3.0 Design Spec

Prepared 2026-11-03 for K. S. Karakostas. Sources: a comparison with Blabby (blabby.ai marketing pages, its public roadmap at blabbyextension.featurebase.app, five screenshots of its extension supplied by K. S. Karakostas), the code on `main` at `aff49fa` (v2.2.0, unit tests 716/716), and the Chrome extension docs cited in section 3.

Companion: `docs/superpowers/plans/2026-11-03-v3-master.md` splits this spec into lanes, each with a kickoff prompt. Each lane writes its own executable plan from this spec and the code as it then exists. The 2.x roadmap (`docs/superpowers/specs/2026-09-26-voicetype-roadmap.md`) keeps its decisions D1 to D12 and its global constraints; its Phase 2 (streaming, command mode, history, onboarding) stays parked and is not part of 3.0.

Tags used below: **VERIFIED** (code at file:line, or the cited doc), **DECIDED** (K. S. Karakostas, 2026-11-03), **PROPOSED** (my call; a lane may change it only with K. S. Karakostas's approval), **SPIKE** (a lane settles it by experiment before building on it).

## 1. Intent

Blabby's users ask for what VoiceType already is (its backlog: "one-off pricing with own API key", 17 votes; "custom API key integration", 12). Blabby is ahead on the settings surface and daily-use polish. 3.0 closes that gap without giving up BYOK, cost per session, or the no-server design.

**Goals**
- A full settings page in a tab; the toolbar popup becomes a quick panel.
- A Home dashboard: words, speaking speed, time saved, days dictated this week, cost per 1,000 words.
- A dictionary grouped by language, with CSV import and export.
- Site rules: hide the pill on a site; a default mode per site.
- Start, stop, done and error sounds; an option to also copy every result to the clipboard.
- Three pill styles: Pill (today's), Dot, Minimal.

**Non-goals:** accounts, credits or a server; a microphone picker or level tester; snippets; dictation history; rewriting a selection; auto-enter; streaming; Chrome Web Store assets; new providers or models.

**Anti-goals** (3.0 fails if any of these happens, even if every feature works)
- A key reaches a content script or a web page, or the offscreen document reads, stores or handles one. (`chrome.runtime.sendMessage` from an extension page is delivered to every extension context, so the offscreen listener drops anything not from the service worker, `src/offscreen/offscreen.js:76`; that check stays.)
- Text lands in a field other than the one focused at REC (D12), or a paid transcript is lost.
- Recording happens with no visible indicator on the page (hidden site included).
- A setting entered on the settings page is lost on close once one second has passed since the last keystroke (section 4.1).
- Any 2.2 behaviour regresses: hold to talk, frames and shadow roots, insertion ladder, orphan handling, password refusal, cost tracking.

## 3. Platform facts this design rests on

- An options page opens in a tab with `options_ui.open_in_tab: true` (or `options_page`); `chrome.runtime.openOptionsPage()` opens it, "may just focus an open options page", and never reloads the caller. VERIFIED: developer.chrome.com/docs/extensions/develop/ui/options-page, /reference/api/runtime. The popup does not use it, since it cannot pass a route (V6). `chrome.runtime.getContexts` (Chrome 116+) accepts `contextTypes: ['TAB']` and returns `tabId`, `windowId` and `documentUrl` per context. VERIFIED: /reference/api/runtime. That `tabs.update` and `windows.update` work on the extension's own tab without the `tabs` permission is checked in L0 step A.
- The settings page is under the extension origin, so the router classifies it as `'extension'` before looking at `sender.tab`. VERIFIED: `src/background/router.js:56-62`. It reads and writes settings through the existing messages (`GET_SETTINGS` returns the full settings with keys to `'extension'` senders, `src/background/router.js:140-143`), so it needs no direct `chrome.storage` access.
- `sender.tab` is present for content-script senders ("including content scripts") and `sender.url` is the frame's URL. VERIFIED: /reference/api/runtime (MessageSender). That `sender.tab` is also present for a cross-origin iframe sender is shown by the passing frames e2e (`test/e2e/frames.spec.js`), whose recording goes through `endpointOf` and needs `sender.tab.id` (`src/background/router.js:117-119`); L3 adds a probe that `sender.tab.url` is the top-level URL there. `Tab.url` is present with host permissions for the page; the manifest holds `<all_urls>`. VERIFIED: /reference/api/tabs, `manifest.json`.
- One offscreen document per extension; `reasons` is an array; only `AUDIO_PLAYBACK` sets a lifetime limit (closes after 30 s without audio); offscreen documents get `chrome.runtime` only. VERIFIED: /reference/api/offscreen. Consequence: never add `AUDIO_PLAYBACK` to the recording document, since 30 s of recording without playback could close it.
- The offscreen document is created with `reasons: ['USER_MEDIA']` and never closed by the extension. VERIFIED: `src/background/offscreen-client.js:22-27`.
- The recording mode is fixed at start from `settings.activeMode`. VERIFIED: `src/background/recorder.js:99`.
- The pipeline sends `settings.keywords` to both providers. VERIFIED: `src/background/pipeline.js:59`. The 100-term cap (`MAX_KEYWORDS`, `src/popup/form.js:14`) is enforced only by the popup's parser (`src/popup/form.js:22-34`); stored-settings validation does not cap (`src/shared/defaults.js:125-128`). Both providers cut each term at 64 characters (`src/background/providers/openai.js:18`, `src/background/providers/gemini.js:25`).
- The usage log is v2 with per-day buckets kept 90 days (`src/background/usage.js:3`, `:43`). `normalizeBucket` rebuilds every bucket from the known fields only and defaults them to 0 (`src/background/usage.js:58-73`, `normalizeLog` at `:82-91`). Trap for L1: a new bucket field is stripped on every read unless `normalizeBucket`, `addTo` and `sumDays` all carry it.
- Release convention: the top `CHANGELOG.md` heading must equal the manifest version (`test/unit/manifest.test.js`). So no lane before L6 adds a changelog heading.
- Not yet verified (SPIKE in L4): whether an offscreen document created without `AUDIO_PLAYBACK` may play audio; whether Chrome's echo cancellation keeps a start cue out of the recording.

## 4. Settings schema v3

`SETTINGS_VERSION` becomes 3. All of the schema lands in L0, so later lanes never edit `src/shared/defaults.js` migrations.

New or changed fields:

| Field | Type | Default | Notes |
|---|---|---|---|
| `dictionary` | `Record<string, string[]>` | `{}` | Key: a code from `SPOKEN_LANGUAGES` or `'any'` (shown as "All languages"). Replaces `keywords`. Display order follows `SPOKEN_LANGUAGES`, `'any'` first. Total terms across groups capped at 100 (`MAX_KEYWORDS`); duplicates (case-insensitive) collapse when sent. |
| `siteRules` | `Record<string, { hidePill: boolean, mode: string\|null }>` | `{}` | Key per V8; L0 creates `src/shared/sites.js` with `siteKey` so validation can normalize keys, and L3 extends that file. A rule with `hidePill: false` and `mode: null` is deleted. A rule whose mode no longer exists falls back to `null`. |
| `pillStyle` | `'pill'\|'dot'\|'minimal'` | `'pill'` | |
| `sounds` | `boolean` | `false` | |
| `alwaysCopy` | `boolean` | `false` | |
| `keywords` | removed | | Migrated into `dictionary.any`. |

Migration (the routing in `migrateSettings`, `src/shared/defaults.js:212`, is rewritten: today it sends anything below `SETTINGS_VERSION` to `migrateV1`, which rebuilds keys from the v1 fields `apiKey` and `geminiKey`, so a v2 store would lose its keys once the version is 3):
- `settingsVersion >= 3`: validate as v3.
- `settingsVersion === 2`: validate as v2 (`migrateV2`), then the v2-to-v3 step.
- anything else: `migrateV1`, then the v2-to-v3 step.
- Unit tests: a v2 store with keys, custom modes and keywords comes out of migration with the same keys, modes and terms.
- v2 to v3: `keywords` (string list) moves to `dictionary.any`, the new fields take their defaults, `keywords` is deleted, `settingsVersion` becomes 3.
- v3 and newer: validate every field and repair only what is wrong, the way `migrateV2` does today.
- Stored data from a newer version is never down-migrated.

Public settings (`toPublicSettings`) exclude `keys`, `siteRules` and `dictionary` (no content code reads the terms; PROPOSED).

Pipeline: `transcribe` receives `keywords: flattenDictionary(settings.dictionary)` (L0).

`SPOKEN_LANGUAGES` and `MAX_KEYWORDS` move from `src/popup/form.js` to `src/shared/` in L0, since `defaults.js` validates the dictionary with them.

### 4.1 How extension pages save (V18)

Today the popup sends the whole settings object on every change (`src/popup/popup.js:146-151`) and never listens for changes; `SAVE_SETTINGS` replaces each top-level field it receives (`src/background/router.js:145-155`). With a settings tab open for hours next to the popup and the pill, that would overwrite newer data. From L0:
- The settings page and the popup send `SAVE_SETTINGS` with only the top-level fields the edit changed (keys only when a key changed).
- Both re-read settings on `chrome.storage.onChanged` (extension pages are trusted contexts) and re-render, keeping any field the user is editing at that moment.
- Text fields save on `input` after a 400 ms debounce, on `blur`, and on `pagehide`. The pagehide flush is a best effort (the popup's comment at `src/popup/popup.js:606-609` explains Chrome's limits); the page does not block closing with `beforeunload`. The L0 smoke checks: type, wait one second, close the tab, reopen: the value is there.

## 5. Message contract changes

| Message | From | Change | Lane |
|---|---|---|---|
| `GET_SETTINGS` | content | Reply adds `site: { hidePill: boolean, mode: string\|null }` for the sender's tab | L3 |
| `SETTINGS_CHANGED` | SW to tabs | Sent per tab with that tab's `site` (today one broadcast for all tabs, `src/background/index.js:58` through `broadcast` in `src/background/tabs.js`) | L3 |
| `SET_SITE_MODE` (new) | content | `{ mode: string\|null }`; the router resolves the host from `sender.tab.url` and updates that rule (V9). A content script can never name a host. `UPDATE_SETTINGS` and `CONTENT_PATCH_FIELDS` stay unchanged. | L3 |
| `SET_SITE_RULE` (new) | popup, settings page | `{ host, hidePill, mode }`, accepted from `'extension'` senders only; the router normalizes `host` with `siteKey` and edits that one rule (an empty rule is deleted). The popup finds the host itself with `chrome.tabs.query({ active: true, currentWindow: true })` (its own window) and reads the current rule from the full settings it already has, so no read message is needed | L3 |
| `START_RECORDING` | content | The SW fixes the mode at start: the site rule's mode when set, else `activeMode` | L3 |
| `OFFSCREEN_COPY` | SW to offscreen | `{ text }`; reply `{ ok }` | L4 |
| `DICTATION_RESULT` | SW to content | Success payload adds `copied: boolean\|null` (null: always-copy off) | L4 |
| `OFFSCREEN_CUE` | SW to offscreen | `{ cue: 'start'\|'stop'\|'done'\|'error' }` | L4 |

New names go in `src/shared/messages.js` only. The router's `ACCESS` map lists only messages the router receives (`src/background/router.js:80-94`), so it gains `SET_SITE_MODE` and `SET_SITE_RULE` (L3); the service worker's outgoing `OFFSCREEN_CUE` and `OFFSCREEN_COPY` do not go in it.

## 6. Features

### 6.1 Settings page and quick panel (L0)

- Files: `src/options/options.html|js|css` (new), `src/popup/*` (rewritten slim), shared UI helpers moved from `src/popup/form.js` into `src/ui/` when both pages use them. `build.mjs` gains the `options` entry and statics. Manifest gains `options_ui`.
- Layout (Blabby-like): a left sidebar, a content area. Sidebar: Home, Modes, Dictionary, then Settings with sub-items Provider, Recording, Speech, Sites, Appearance, Sound and clipboard, Usage; footer: version and "by K. S. Karakostas". Hash routes (`#home`, `#modes`, `#settings/provider`, ...) so a reload keeps the place and the popup can open a route (V6). Settings sub-items: Provider, Recording, Speech, Sites, Appearance, Sound and clipboard, Usage and data.
- L0 moves today's popup sections unchanged in behaviour: Provider (keys, Test, Clear, spend hint) to Settings, Provider; Recording (limits, silence auto-stop, hotkey recorder) to Settings, Recording; Speech (spoken languages, vocabulary) to Settings, Speech, where the vocabulary textarea now edits `dictionary.any` and its count shows the total across groups (L2 replaces it with the Dictionary page); Modes to Modes; Usage table, Clear history and Reset to defaults (V21) to Settings, Usage and data; About's version, byline and links to the sidebar footer. Pages that later lanes fill (Home, Dictionary, Sites, Appearance, Sound and clipboard) show a one-line placeholder in L0.
- Saving: every control autosaves as today; on a page a text field also saves on `input` after a short debounce and on `pagehide`, so input survives a close one second after the last keystroke (anti-goal, section 4.1). L6 removes the popup Esc workaround from the README.
- Popup quick panel: status line (ready, or "Add API key" linking to Settings, Provider); provider segmented control; active mode select; "This site" block (hostname, Hide pill switch, Mode on this site select: "Use active mode" plus every mode) from L3, a placeholder before; today's sessions and cost; Open settings button (V6). Popup width stays 320 px.
- Both pages follow `prefers-color-scheme`, keep visible focus rings and keyboard order, and set user data with `textContent` only.
- Acceptance: every 2.2 setting is reachable and persists from the page; closing the tab one second after typing keeps the value; the pill menu reflects a change within one second; the popup opens a route, reusing and focusing an open settings tab; Reset keeps the V21 fields; unit tests cover migration v2 to v3 and the slim popup.

### 6.2 Home dashboard (L1)

- Usage log: each bucket gains `words` (raw transcript words), `wordSeconds` (audio seconds of the sessions that counted words) and `wordCost` (cost of those sessions). Version stays 2. `normalizeBucket`, `addTo` and `sumDays` all carry the three fields (section 3 trap); old days read as 0, so sessions before 3.0 never skew a word-based number.
- `dictate.js` counts words of `result.raw` (V15) and passes them with the usage entry.
- Summary gains a `thisWeek` bucket (V16) and the list of days in this week with at least one session.
- Home shows, for this week: time saved (`words / 40` minutes minus `wordSeconds / 60`, floored at 0, shown as "about"), "N min talking instead of M min typing", words this week and all time, speaking speed (`words / wordSeconds * 60`, shown when `wordSeconds >= 30`), sessions refined by a mode (sessions whose mode is not `default`), days dictated (seven squares, Monday first), cost this week, and cost per 1,000 words (`wordCost / words * 1000`, shown when words >= 100).
- Empty state: a short "Dictate once to see your stats" line.
- Acceptance: pure functions for every number with unit tests at the thresholds; a log from 2.2 (no words) renders without NaN or negative values.

### 6.3 Dictionary (L2)

- Page: one card per group (`'any'` first, then languages in `SPOKEN_LANGUAGES` order); Add language (only languages not yet present); a chip per term with remove; an add-term input (Enter adds; commas split); a group remove with an inline confirm like Clear history; the 100-term total shown. Adding a term that already exists in any group (case-insensitive, V20) is refused with "Already in <group>".
- CSV export: `language,term` header, one row per term, language as code (`any`, `en`, ...), UTF-8 with BOM for Excel. Download through a Blob URL from the page.
- CSV import: accepts the export format, and a one-column file (each line a term, into `any`). Quoted fields per RFC 4180. Unknown language codes are rejected with the line number. Merges into existing groups, skipping terms that already exist in any group (V20). If the result would exceed 100 terms, nothing is imported and the message says by how many it is over. Terms are trimmed; empty terms dropped; a term over 64 characters rejected (Gemini's hint sanitizer cuts at 64, `src/background/providers/gemini.js:25`).
- Acceptance: export then import of the same file changes nothing; the parser has unit tests for quotes, BOM, CRLF, blank lines, unknown codes and the cap.

### 6.4 Site rules (L3)

- Resolution: `siteKey(url)` (V8) in a shared pure module; `ruleFor(settings, url)` returns `{ hidePill, mode }` with a missing mode mapped to `null`. Non-http(s) URLs have no rule.
- Content: `controller` gets `site` with the settings. With `hidePill`, the idle pill never shows; recording, processing and statuses use the Minimal presentation (V10).
- Mode: the recorder fixes `modeKey` at start from `ruleFor(...).mode ?? settings.activeMode` (currently `src/background/recorder.js:99`). Only a rule with a mode counts for V9; a hide-only rule leaves mode choice global. On a site with a mode rule the pill shows that mode as active, marked "This site", and lists "Use active mode" first; choosing a mode sends `SET_SITE_MODE` with it, and "Use active mode" sends `null`, which clears the rule's mode (and deletes the rule when it does not hide the pill). Translate's target language stays global.
- Popup: the "This site" block reads the active tab (`chrome.tabs.query({ active: true, currentWindow: true })`, URL present through host permissions) and edits its rule; shows "Not available on this page" for `chrome://`, the Web Store and non-http(s) tabs.
- Settings, Sites: a table of rules (site, Hide pill, Mode, remove) and an "Add site" input that accepts a hostname or URL.
- Acceptance: a hidden site shows no idle pill in the top frame and in its iframes, the hotkey still records there with a visible indicator; a site mode applies to dictations started in its iframes; a content script cannot change another site's rule (router test).

### 6.5 Sound and clipboard (L4)

- SPIKE first, both in a real Chrome 140+ build: (a) does a cue play from the offscreen document created with `['USER_MEDIA', 'CLIPBOARD']`; (b) does `execCommand('copy')` with a textarea in the offscreen document write the clipboard while a web page has focus; (c) does a start cue played just before capture appear in the transcript (record silence plus the cue; expected "No speech detected"). The lane records the results in its ledger and picks the path (V12, V13) before building.
- Cues: start (recording started), stop (processing started), done (the dictation succeeded, before delivery), error. Rule for error: it plays when something failed that the user did not cause; it never plays for a cancellation, a refusal (password field, frame without focus, another tab busy), "Too short, ignored" or the permission prompt. Today's signals cannot tell every case apart (a user cancellation and a real microphone failure both return `micError`, `src/background/recorder.js:89`, `:92`, `:118`, `:136`; an offscreen failure goes through `failSession`, `:64-68`), so L4's plan enumerates every failure path in `recorder.js` with its cue and adds the internal flag it needs, each with a unit test. An insert that later falls back to click-to-copy plays no second cue.
- Always copy: on a successful dictation the service worker copies the text through the offscreen document before it sends `DICTATION_RESULT`, and reports `copied`. The copy waits at most 1 s; no answer counts as `copied: false`, so a stuck offscreen document never holds back a paid transcript (anti-goal). The content script then inserts as today; a clipboard fallback copies the same text again, which is harmless. A failed always-copy never turns "Done" into an error; the controller appends " Not copied." to the Done status. Off by default; the setting's hint says it replaces whatever is on the clipboard.
- Acceptance: with both settings off, no offscreen message is sent for cues or copies (unit test); with sounds on, each cue fires once per event; always-copy puts the text on the clipboard after an insert into a textarea, a contenteditable and a field in a cross-origin iframe.

### 6.6 Pill styles (L5)

- Pill: today's behaviour.
- Dot: an 8 to 10 px dot at the pill's anchor position, same placement rules; it expands to the full pill on hover, on keyboard focus of the dot, and whenever the state is not idle or a status shows; it collapses 300 ms after the pointer leaves and the state is idle. The dot is a button with an accessible name ("VoiceType, open controls").
- Minimal: nothing while idle. While recording or processing, a small non-interactive indicator (level bars, elapsed time) fixed at the bottom centre of the recording frame's viewport (V19), `pointer-events: none`. Statuses show at the same place; a clickable status (click to copy) is the one interactive exception. The menu is not reachable in Minimal; the popup and the settings page are.
- Settings, Appearance: three cards with a small static preview each, like Blabby's; the choice saves at once and reaches open tabs within one second.
- Acceptance: each style renders and works on `test/fixtures/fields.html` (frames, shadow roots) and `test/fixtures/hostile.html` in e2e, and right-to-left in unit tests. Today `hostile.html` is used by no e2e spec and no right-to-left fixture exists, so L5 builds this coverage; Minimal never takes a click outside a clickable status; reduced motion keeps the indicator static.

## 7. Global constraints (in addition to the 2.x roadmap section 3)

- No new permissions beyond what the manifest has; `options_ui` is a manifest key, not a permission. The manifest test gets updated in L0 for `options_ui` and in L6 for the version.
- `minimum_chrome_version` stays 140.
- Zero runtime dependencies; CSV parsing and the dashboard are written in-house.
- No em or en dashes anywhere. In files K. S. Karakostas; never "Kostas".
- Every lane ends with `npm test` and `npm run test:e2e` green, `npm run build` clean, a lane ledger and a browser smoke checklist.
- Commits carry only the change description; no AI attribution trailers.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Per-tab `SETTINGS_CHANGED` costs more messages than one broadcast | One `tabs.query` per change, as today; the per-tab payload differs only in `site` |
| A start cue gets transcribed | L4 spike; if it leaks, play the cue before capture starts and delay capture by the cue length |
| The offscreen document cannot play audio without `AUDIO_PLAYBACK` | Fall back to the content script (V13); never add `AUDIO_PLAYBACK` to the recording document |
| Dot or Minimal hides a sticky click-to-copy status | Statuses always render, in every style (6.6) |
| Settings page, popup and pill write settings at once | All writes go through the queued `storage.updateSettings`; pages send changed fields only and re-read on change (4.1) |
| Dictionary over 100 terms after migration | v2 storage held at most 100 terms only because the popup was its sole writer; v3 validation caps the total at 100 (keeping the first 100 in display order) so hand-edited storage cannot exceed it |
