# VoiceType 3.1 Design Spec

Prepared 2026-11-04 for K. S. Karakostas. Extends `docs/superpowers/specs/2026-11-03-v3-design.md` (cited as "3.0 spec"), whose decisions V1 to V23, anti-goals and global constraints stay in force except where this spec says otherwise. Sources: the code at `4178f46` (v3.0.0), the L6 ledger's Deferred list, section 7 of `docs/superpowers/specs/2026-09-26-voicetype-roadmap.md`, and the answers recorded in `docs/superpowers/plans/2026-11-03-v3-l7-ledger.md`.

Tags as in the 3.0 spec: **VERIFIED**, **DECIDED** (K. S. Karakostas, 2026-11-04), **PROPOSED** (changed only with K. S. Karakostas's approval).

## 1. Intent

**Goals**
- Translate's target language can be set off the pill, so Minimal and hidden sites are not stuck.
- A short history of recent dictations, Insert last, Copy last and Undo AI edit.
- A first-install page.
- A tagged release builds itself: tests, lint, a zip on a GitHub Release.
- The six deferred items chosen from the L6 ledger.

**Non-goals:** command mode, streaming, a microphone picker, snippets, auto-enter, the Chrome Web Store, new providers. The 3.0 spec's non-goal "dictation history" is reversed here; streaming and rewriting a selection stay out.

**Anti-goals** (3.1 fails if any of these happens): the 3.0 list, and:
- History text reaches a content script of a site other than the one it was dictated on.
- History reaches disk, or holds anything with the toggle off.
- A history action puts text in a field other than the one focused at the click, or in a password field.
- Undo AI edit overwrites anything but the exact text VoiceType inserted.
- A history or usage write delays or loses a paid transcript.

**Measured, no change needed:** a worker left to idle during a 45 s provider call is not killed; the transcript lands. The L7 ledger has the numbers. A crash during processing still loses transcript and audio, and history cannot help: no text exists yet.

## 3. Message contract changes

| Message | From | Change |
|---|---|---|
| `GET_LAST_DICTATION` (new) | content | Reply `{ entry: { raw, text } \| null }` (V28) |
| `GET_HISTORY` (new) | popup, settings page | Reply `{ entries: Entry[] }`, newest first; `'extension'` senders only |
| `CLEAR_HISTORY` (new) | settings page | Reply `{ success: true }`; `'extension'` senders only |

New names go in `src/shared/messages.js`, and in the router's `ACCESS` map. `toPublicSettings` leaves out `keepHistory` (`PRIVATE_FIELDS`).

## 4. Features

### 4.1 History

- `src/background/history.js`: `createHistory({ area })` with `add(entry)`, `list()`, `lastFor(host)`, `clear()`. Writes go through one promise queue, as `storage.js` does, so two adds lose nothing. Reads come from `area` each time: the worker may have restarted since the last add.
- `dictate.js` adds the entry after a success, when `settings.keepHistory` is true, inside the V34 limit. The entry exists even when the tab closed meanwhile.
- `recorder.js` holds `host` on the session from the `tabUrl` it already gets, and passes it to `dictate` with the mode.
- The worker clears history when a settings change turns `keepHistory` from on to off.
- `chrome.storage.session` is emptied by a browser restart and by an extension reload, update or disable. VERIFIED by the Chrome storage docs; a smoke row runs it.

Acceptance: a dictation adds one entry; the 21st drops the oldest; toggle off clears and adds nothing; a content script's `chrome.storage.session` read fails; a site never gets another site's entry; the entry's text is set with `textContent` everywhere.

### 4.2 Pill menu

"Last dictation" shows only with an entry for this site. Actions need the page idle with nothing landing; otherwise "Still processing". Each closes the menu. Statuses: "Inserted.", "Copied to clipboard.", "Original text copied.", and the existing click-to-copy on a failed copy.

### 4.3 Popup

Copy last sits under Today, enabled when `GET_HISTORY` returns an entry. It copies `text` with `navigator.clipboard.writeText` and shows a toast. With no entry it is disabled. With `keepHistory` off it is hidden.

### 4.4 Onboarding

`onInstalled` keeps its other work. A failed tab open is ignored. An update never opens it, nor does a browser start. The Open settings button reuses an open welcome tab, as it does any settings tab.

### 4.5 Release

The zip holds `dist/` at its root, so "Load unpacked" works on the extracted folder. Notes come from the CHANGELOG section matching the tag, through a small script with a unit test. Before a tag the workflow cannot be run for real: the steps are run locally, and the first tag is its real test (TO CONFIRM, K. S. Karakostas, at the 3.1.0 push).

## 5. Global constraints

Unchanged from the 3.0 spec, section 7: `minimum_chrome_version` 140; no new permission without K. S. Karakostas's approval; keys never reach content scripts or pages, and the offscreen document never handles one; user data set with `textContent` only; zero runtime dependencies (`web-ext` is development only); no em or en dashes; commits carry only the change description, no AI trailers; all subagents on Opus (V22); in files K. S. Karakostas.

## 6. Risks

| Risk | Mitigation |
|---|---|
| The welcome tab on install breaks tests and harnesses that count tabs | `launchExtension` and the harness `launch` close it; a test pins that it opens |
| Transcripts kept in memory surprise a user | On the History page, in README and PRIVACY; a toggle clears them |
| `web-ext` brings a large dev tree and audit noise | Dev only; `npm audit --omit=dev` stays the gate |
| The workflow is first really run by the 3.1.0 tag | Each step run locally; a failed run publishes nothing, as the release step is last |
