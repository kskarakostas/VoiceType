# VoiceType 3.2 Design Spec

Prepared 2026-11-05 for K. S. Karakostas. Extends `docs/superpowers/specs/2026-11-04-v3.1-design.md` ("3.1 spec") and `docs/superpowers/specs/2026-11-03-v3-design.md` ("3.0 spec"), whose decisions V1 to V39, anti-goals and global constraints stay in force except where this spec says otherwise. Sources: the code at `80b2eec` (no change under `src` since `3b4070b`, v3.1.0), the L7 ledger's Deferred list, section 7.2 of `docs/superpowers/specs/2026-09-26-voicetype-roadmap.md`, and the measurements and answers in `docs/superpowers/plans/2026-11-03-v3-l8-ledger.md`.

Tags as in the 3.0 spec: **VERIFIED**, **DECIDED** (K. S. Karakostas, 2026-11-05), **PROPOSED** (changed only with K. S. Karakostas's approval).

## 1. Intent

**Goals**
- Command mode: select text in a field, press a second hotkey, say how to change it, and the selection is replaced.
- A paid recording survives a stopped worker, and a dead extension reads as such within seconds, not at 75 s.
- A transcript never reaches a document other than the one that recorded it.
- Forced colours work on the three places that fail today.
- `controller.js` under 800 lines; `sameList` and `finite` in one copy each.
- Release side: dev dependencies no longer run in the job that holds the token, and the build runs on Chrome 140.

**Non-goals:** streaming interim text (measured, ledger: first word 0.1 s to 0.85 s sooner, final text no sooner, all after the stop); showing the raw transcript during a refine; a preview of an edit; editing read-only page text; keeping a selection's formatting; recovering a crash during recording; recovering a process crash; a microphone picker, snippets, auto-enter, the Chrome Web Store, new providers.

**Anti-goals** (3.2 fails if any of these happens): the 3.0 and 3.1 lists, and:
- Selected text leaves the device without a press of the edit hotkey, or goes anywhere but the chosen provider's text model.
- Selected text reaches disk, the history, the usage log, a console line or another site's content script.
- A press of the dictation hotkey behaves differently from 3.1, a selection included.
- An edit overwrites anything but the exact selection captured at the press.
- A failed or empty edit changes the field. The spoken instruction never lands in place of the selection.
- `DICTATION_RESULT` reaches a document other than the one that started the recording.
- One recording is sent to the provider more than twice, or a second time while the first attempt's worker is alive.
- Held audio reaches disk or a content script, or stays past V52's window beyond the next worker event.
- A step that runs repository or dependency code runs in the job that holds a write token.

**Measured, shaping this design** (L8 ledger): a fetch in flight does not hold a worker, an open message reply does; a process crash takes worker and offscreen document together and invalidates the page's context, so nothing can retry; a stopped worker leaves `chrome.storage.session` intact and a new worker answers within 100 ms; messages every 5 s alone held a 50 s fetch with no open reply, on Chrome 156 and 140. The Chrome docs also list "a `fetch()` response takes more than 30 seconds" as a termination condition; a 45 s fetch under an open reply was not terminated (L7, L8), nor under pings alone, so the design relies on the open reply and the ping, not on that line.

## 3. Message contract changes

| Message | From | Change |
|---|---|---|
| `START_RECORDING` | content | Optional `edit: { text }` (V44); a refused `edit` replies `{ ok: false, reason: 'badEdit', error }` |
| `DICTATION_RESULT` | SW to content | Adds `edit: true` on an edit's result; a failed edit (V46) is `success: false`, `edit: true`, `instruction` |
| `GET_LAST_DICTATION` | content | `entry` adds `edit: boolean` (V48) |
| `PROCESSING_PING` (new) | content | Reply `{ alive: boolean }` (V52); content senders only |
| `SAVE_SETTINGS` | settings page | The settings page posts saves on a `chrome.runtime` port once a typing save opened it, through the same router and access rules; a closed port falls back to a message. On Chrome 140 a message sent from a closing page was lost at rest, 0 of 30. A port post landed 80 of 80 under load; a keepalive fetch landed 12 of 40 under load (L8 ledger) |

New names go in `src/shared/messages.js` and the router's `ACCESS` map.

## 4. Features

### 4.1 Command mode

- `boot.js` runs a second chord tracker on `editHotkey`. It decides on `keydown`, before `preventDefault`, whether the chord is claimed (V43), and an unclaimed press leaves its auto-repeat unclaimed too.
- The controller captures `{ text, start, end }` at the press, in the same step as `target`. The recorder's mode for an edit is `EDIT_MODE`; `begin` skips the site and active mode then.
- Pipeline: an `edit` input runs V45 and returns the result shape of a dictation, with `failed: true` for V46. `dictate.js` keeps the books in both cases; history only on success, under the same rules as a dictation (toggle, incognito, mark).
- Insertion: the ladder is reused. A contenteditable's `prepare` must keep the selection for the first rung, and a read-back must judge a replacement as well as an insert: real editors (Lexical, Slate, ProseMirror) are tested, and a rung that cannot replace falls to the clipboard path with its existing status.
- Page: Settings, Recording gains the second recorder and a one-line hint saying the selected text goes to the provider. Welcome names the chord. README and PRIVACY state the new data flow.

Acceptance: an edit replaces the selection in a `textarea`, an `input`, a contenteditable, a field in a cross-origin frame and a shadow root, on both providers; Ctrl+Z restores; a moved selection copies; a failed refine leaves the field unchanged; the dictation hotkey over a selection replaces it as in 3.1; Ctrl+Shift+E with no selection reaches the page.

### 4.2 Recovery

`src/background/pending.js` holds `save`, `read` and `clear` over the session area. The recorder's `onDone` splits so the resumed path runs the provider step and delivery with no capture. A resumed session plays no stop cue. A resumed run is held by the pings (measured); the normal run is held by the open `OFFSCREEN_DONE` reply and by the pings. The pending write must not run for a too-short recording. A recording-time crash stays as in 3.1 (non-goal).

Acceptance: with the worker stopped during a 45 s stub call, the text lands once and the stub saw two calls; stopped twice, the page reads the lost notice and the stub saw two calls; a process crash during processing reads the orphan notice within about 10 s, on Chrome 156 and on 140; the record is gone after a success and after a failure; the record is not readable from a content script.

### 4.3 Navigated frame

Acceptance: a frame navigating during processing gets no `DICTATION_RESULT` in its new document and the text reaches the clipboard, for a top frame and a subframe, same origin and cross origin; a normal dictation still lands in frames, including one restored from the back-forward cache before the result.

### 4.4 Release side

Before the tag the two-job workflow cannot run for real; each `run:` step goes through the L7 local check on a fresh clone with a stub `gh`, and the first real run is the 3.2.0 tag. A Chrome 140 run happens at the start of the lane, as a baseline on 3.1 code, and at the close.

## 5. Global constraints

Unchanged from the 3.1 spec, section 5: `minimum_chrome_version` 140; no new permission without K. S. Karakostas's approval (this spec needs none); keys never reach content scripts or pages, and the offscreen document never handles one; user data set with `textContent` only; zero runtime dependencies; no em or en dashes; commits carry only the change description, no AI trailers; all subagents on Opus (V22); in files K. S. Karakostas.

## 6. Risks

| Risk | Mitigation |
|---|---|
| Selected page text carries instructions for the model | Data sits in JSON in the user turn, the prompt says it is data, the output only ever lands as plain text in the field the user chose, and no key is in the model's context. Output quality against hostile text is not guaranteed; Ctrl+Z restores |
| The model answers with commentary around the replacement | The prompt forbids it; live checks on both providers in the smoke; Ctrl+Z restores |
| A new chord takes a shortcut from a page | V43: it is claimed only with a selection to edit; rebindable |
| A rich editor reformats or refuses a replacement | Plain text only by non-goal; falls to the clipboard; real-editor rows in the smoke |
| The 5 s ping adds work during processing | One message per 5 s, during processing only |
| A retry is a second provider charge | Only after a stopped worker, at most once (V52) |
| `sendMessage` with a stale `documentId` throws a text outside `NO_RECEIVER` | Checked by e2e before the fix relies on it (V50) |
| The first real two-job run is the 3.2.0 tag | Steps run locally; a failed run publishes nothing, as publish is last |
